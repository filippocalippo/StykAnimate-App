# Implementation and acceptance status

This document describes the current StykAnimate-webapp source. The supplied Pivot executable and real PIV/STK files define compatibility expectations. The separate [Pivot acceptance checklist](PIVOT_PARITY.md) records which expectations have sufficient evidence. A runnable package or successful screenshot alone does not establish complete parity.

## Current performance measurements

The prepared pipeline supersedes the initial main-thread playback implementation. On the 1,000-figure / 24-key test at 60 FPS, [the recorded run](../artifacts/renderer-ui-performance-60fps.json) reached 59.88 warm effective FPS. Renderer submission p95 was 0.2 ms; the editor render section, including first-use packet work, was 0.4 ms p95. Startup-to-first-frame was 93.4 ms. The worker prepared the 24 packets in 518.6 ms; cached packets consumed 27.36 MB on the CPU and 25.73 MB on the GPU. These measurements exclude OS input, completed GPU work, and display latency; worker misses can require preparation.

On Akane's final keyframe (643 figures, 15,054 segments), [incremental editing](../artifacts/renderer-edit-profile/report.json) took 1.7 ms p95 for translation, 1.4 ms for a parent and eight joined descendants, and 5.7 ms for a 105-object connected rig, counting mutation, geometry, and renderer submission. All 72 edits used changed-slot preparation; final GPU images matched a fresh full compile. Cold frame switches still compile a new scene. The 30,000-joint chain/star fixtures in [large-figure performance](../artifacts/large-figure-performance.json) exercise stack-safe traversal, not interactive 60 FPS at that extreme.

The earlier Akane autosave performed whole-document serialization on the UI thread and recorded an 8.84-second animation-frame gap. The [worker snapshot/export version](../artifacts/edit-freeze-16-akane-vs-akato-segundo-round--3--after-worker/report.json) completed its actual recovery copy with zero UI long tasks in the autosave phase, a 7.0 ms p95 animation-frame interval, and a 62.5 ms maximum interval. The entire background phase still lasted about 27.7 seconds. This demonstrates responsive scheduling during expensive work; it does not mean the file was saved in 7 ms. That same report contains one 55 ms numeric-edit task, so it must not be described as a globally zero-long-task run.

Backend import and encoded-response preparation for the exact Akane source improved from [10.92 s](../artifacts/backend-akane-profile.json) to [4.84 s](../artifacts/backend-akane-profile-after.json). Binary decode remained approximately 4.21 s. Removing redundant modern-file validation and using optional compiled JSON encoding reduced the other work; peak backend working set fell from 1.055 GB to 0.869 GB. These single-run process timings exclude file reading, HTTP transfer, frontend reconstruction, and rendering. The exact native restart round-trip is verified separately.

The [native 200 MiB transport test](../artifacts/native-streams-smoke.json) measured 2.37 s file saving, 2.11 s recovery writing, and 1.28 s recovery reading, with zero renderer long tasks and exact SHA verification. It also verified cancellation preserves the prior destination. A 60.4 ms maximum renderer timer gap remains in that run; timer gaps include scheduling and are not input-to-display measurements.

The [complete Akane playback audit](../artifacts/edit-freeze-16-akane-vs-akato-segundo-round--3--full-playback-budgeted/presentation-summary.json) submits all 1,872 output ticks in exact order, without preparation or browser errors. Both packet caches remain within 128 MiB. First-to-last submission takes 117.264 seconds against 116.938 nominal at 16 FPS; intervals are 69.5 ms p95 and 70 ms p99. Remembering packet sizes prevents repeated over-budget prefetch rasterization: the previous dense-scene backlog is removed. Isolated delays remain, including a 363.1 ms maximum. The next frames were already available during the largest two delays, so these require separate GPU/compositor investigation rather than further cache-miss fixes. See [the before/after findings](../artifacts/edit-freeze-findings.md).

## Architecture and limits

See [ARCHITECTURE.md](ARCHITECTURE.md) for module boundaries and resource budgets, [document exports](document-exports.md) for cancellation/revision requirements, and [image exports](image-exports.md) for format limits. Compiled acceleration uses Chromium/WebGPU, native compression and numeric unpacking, and the optional JSON encoder. The persistent Python sidecar retains the existing authoritative binary grammar.

The current source has broader coverage than the initial baseline, but full Pivot parity and unconditional zero lag are not claimed. Remaining acceptance work includes broader positioning/IK and builder option coverage, full export/codec matrices, font/platform coverage, and exhaustive native reference comparison. Keep behavioral, binary, raster, scheduling, and packaged-build evidence separate.
