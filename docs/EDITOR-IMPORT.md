# Editor import preparation

`await editor.loadAsync(document, name, options)` validates an incoming decoded Pivot report, prepares its UID/layer/timeline indices in cooperative tasks, and publishes it with one `document` event. Native Pivot imports can use `initialFrameIndex: 'last'`; `initialTick` optionally seeks before that event. The synchronous `load` method retains the same report schema and uses the same validators and preparation code.

Options are `signal`, `sliceMs` (default 4; greater than zero and at most 16), `onProgress`, `initialFrameIndex`, `initialTick`, and `prepareScene`. Tests can inject `yieldControl`; production uses the browser scheduler with a MessageChannel fallback. Checkpoints cover native figure topology, all object poses and joins, camera/background/style fields, layer assignments, authored keys, retained frame sources, source identities, and index construction. Async loading does not trust a decoder to have validated the editor's semantic constraints.

The optional `prepareScene({report, frameIndex, tick, frame, signal, checkCurrent})` callback runs after validation and before publication. It receives the exact evaluated initial frame, including a restored Simple working-frame target, and returns `{geometry}` after preparing media and renderer resources. Cooperative callers use `checkCurrent()` around each await; the editor checks again before adopting that exact frame and geometry. Resource staging must leave the live renderer untouched until publication. The `document` event includes `scenePrepared: true` when this cache is installed, allowing the app to activate its matching staged resources before the next paint. Failed or cancelled preparation retains the old document, selection and history.

The caller transfers exclusive ownership of the incoming report. Preparation may normalize its metadata and assign missing stable source IDs; poses and media are never copied. The current editor report, history, selection and identity allocators remain intact until preparation succeeds. Abort, a newer load, or an edit/gesture on the current document cancels publication. Callers must not mutate an incoming report while it is being prepared. Loading the currently open report through the async method is rejected.

`editor.lastLoadTimings` records preparation work/slice durations, optional `sceneMs`, and publication/listener durations. A time-slice budget is a scheduling target rather than a hardware-independent latency guarantee: garbage collection, a single unusually large pose and synchronous event listeners can take longer. Actual file profiling remains part of import acceptance.

Native Pivot permits zero stored keyframes. Such imports normalize to one internal editable placeholder with `_styk.simpleFrameDraft.empty: true`. When Simple mode is enabled, `editor.timeline` is empty and `totalTicks` is zero. Stored-frame export excludes the placeholder; the first Add promotes it. Normal Simple Add drafts likewise expose the stored baseline's duration while edits continue in the working pose.

Tests: `tests/editor-load.test.mjs`, `tests/editor-load-scene.test.mjs`, `tests/animation-validation-steps.test.mjs`, and `tests/editor-frame-draft.test.mjs` cover equivalent sync/async results, single-event publication at the requested frame, prepublication scene cache adoption, late invalid fields, cancellation and replacement races, and stored/empty timeline semantics.

The source-stable Akane desktop diagnostic in `artifacts/matched-app-interaction-cpp-async-clean-v1/report.json` recorded 210/184 ms of preparation across 39/34 cooperative slices, maximum slices around 8 ms and 2.4/2.3 ms of synchronous document listeners. Validation produced no import long task. The remaining 67/52 ms tasks were the first geometry/render/timeline pass after publication; those are tracked separately from loader validation. These are one cold and one warm diagnostic, not a claim that every file or device has the same latency.
