# Rig topology and animated styles

Segment opacity and gradient endpoint opacity follow physical segments through rig editing. Set Origin remaps their handle targets along the reversed path. Split and Duplicate Branch copy the affected curves to new segments, using fresh key identities while preserving the original keys. Delete, branch deletion, Unsplit, and replacement definitions remove only style targets whose physical segments disappear. Unsplit preserves the surviving children's styles.

Captured instance styles in native frames and retained pose sources use the same mapping. Other figures, surviving branches, outline opacity, channel metadata, interpolation, and key timing are preserved. The existing topology command carries the affected pose snapshots and a sparse channel patch, so the complete operation is one undo step. Invalid mappings or exhausted key identities roll back definitions, poses, styles, and metadata together.

Simple timeline drafts keep their stored baseline separate from the working pose during shared rig changes: the session detaches the affected baseline objects before mutation, so a shared object is never transformed twice, and topology history includes explicit baseline pose entries. Shared rig edits do not append a frame.

When one UID uses different rig definitions across source frames, the affected legacy style curve splits into definition-specific targets: `{kind:'segment',uid,handleId,figureTypeId}`. Only the edited rig's physical handles and gradient roles change. Other rig curves retain their values, timing and interpolation; native frames and retained sources belonging to other rigs remain untouched. This uses the original continuous curves without sampling or baking. Explicit scoped curves take precedence over legacy global curves, including when both coexist before a topology operation.

Unscoped channel IDs remain backward compatible. Scoped IDs include `@figureTypeId` in their encoded segment identity, and timeline rows identify their rig. `segmentAnimationTarget(uid,handleId,property)` (a session read) resolves an existing scoped variant for the displayed rig; an explicit scoped target is never silently redirected. A dormant rig row retains editable existing keys, while sampling or adding a current-pose value requires that rig to be displayed.

Verification includes sparse handle IDs, native and retained source styles, key identity independence, untouched figures, atomic capacity failure, one-step undo/redo, real PIV/STYK export and reopening at every output tick, and Simple baseline alias/history tests. Mixed-rig checks cover Set Origin, Split, Duplicate Branch, branch deletion, Unsplit, single-segment deletion, repeated edits of both rigs, and overlapping scoped/global curves.
