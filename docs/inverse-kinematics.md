# Per-node inverse kinematics

Select a node in Animate and enable **Is IK** under **Transform**. **Pinned** starts checked. **Chain** counts incoming bones toward the connected rig's root, crossing figure joins (two for a thigh/shin or upper arm/forearm). A join shares a vertex and does not add a bone to the count. Drag the node to pose the chain. IK changes only its outline to blue; its normal circular shape, fill, and size are retained.

Pinned targets retain their world position and outgoing orientation while the root moves, including live canvas drags, playback, and inbetweens. For a leg, enable IK at the ankle with a two-bone thigh/shin chain: the foot follows the ankle target's orientation, so moving the hip leaves the whole foot planted. **Rotation** turns the outgoing group around the target and keeps that new orientation planted. **Direction** offers Left, Both, and Right. Explicit sides choose opposing solutions. Both is the default: it preserves the current bend during ordinary motion, and considers the opposite solution near extension or when crossing the folded region. It chooses the solution that reduces knee motion, with a dead band to reject tiny fluctuations. At a fully folded equal-length limb, it preserves knee orientation instead of choosing an arbitrary axis.

**Allow stretch** uniformly extends the chain only when the target exceeds its reach. Pinned chains keep their authored rest lengths and return to them when the target comes back within reach. Foot lengths and unrelated limbs are unaffected. Without stretch, the endpoint stops at the chain's reach; drag the normal node back to recover. There are no separate square targets or extra canvas overlays.

IK uses a virtual target space without changing the stored skeleton hierarchy. Every branch leaving the IK endpoint inherits the target's rotation; its descendants receive the same correction once, preserving local articulation and polygon shapes. This applies equally to static construction nodes, ordinary descendants, and joined figures. Branches leaving earlier joints in the chain still follow those solved bones. No foot classification or extra rig objects are required. Ordinary FK edits inside the outgoing group update its articulation relative to the target, while ancestor and root rotations keep the target orientation fixed. Without stretch, an unreachable foot remains connected at the chain's reach and retains its target orientation.

Unpinning bakes the displayed solution, including stretched lengths, without a jump. Dragging an unpinned target still solves the chain while preserving the outgoing group's orientation. Ordinary figure/FK transforms carry the unpinned limb with the body. Unpinned stretching uses the gesture's starting lengths to avoid cumulative growth. Re-pinning captures the current endpoint position and outgoing orientation. Disabling IK preserves the displayed pose.


## State and evaluation

- `src/ik.mjs` is independent of the DOM, editor, renderer and codecs. It implements the numerical solve, controller validation, interpolation, and explicit placement offsets for copied rigs.
- Each pose object stores `_stykIK`, keyed by stable endpoint handle ID. Active solve state consists of enabled/pinned/allowStretch, chain length, bend direction, target position and rotation, outgoing follower offsets, and bend continuity. `followers` and `joinedFollowers` capture the outgoing branches' angles relative to target rotation. Older partial follower tables inherit the captured group's rotation, preserving the shape of all outgoing branches. Legacy attachment-offset tables remain readable but do not split branches into different rotation spaces.

- Controls are authored with the instance's pose, not the shared figure definition. They carry into duplicated/new frames and authored pose keys. Existing different poses are not silently rewritten. Pin/enabled/chain changes are discrete; compatible target positions, rotations and outgoing offsets use the existing interpolation/easing evaluator.
- `solveObjectIK` returns derived angles, optional stretched lengths, and solve diagnostics without mutating source objects. The common geometry builder invokes it after resolving joined roots. Editor, worker playback, onions, thumbnails and image/vector rendering therefore share the same constraint result. There is no post-render constraint adjustment.
- `src/ik-evaluation.mjs` separates pose solving from artwork rebuilds. Its document-owned cache compares numeric topology, root, angles, effective lengths/bends, scale, and controller state by value. Thickness, color, opacity and other appearance fields do not invalidate a solve. In-place pose edits, undo, topology changes and timeline seeks still invalidate the relevant result. It retains at most 1,024 solutions / 250,000 bones per document, without retaining frame objects or relying on mutable object identity.
- Two-bone chains use an analytic solve. Longer chains use up to 32 FABRIK passes, with a deterministic bend seed at collinear singularities. Zero lengths, curved-link chord lengths, unreachable targets and coincident endpoints are handled. Long chains may retain a residual error at the iteration limit. Stretch allocates a derived length array only when enabled and needed.
- Both controllers retain a compact `bendReference` (side, pole angle, endpoint axis and normalized distance). Longer chains additionally retain solved chord directions so FABRIK continues their shape instead of restarting from the original rig pose. The editor updates this reference from the existing scoped geometry evaluation. It travels with pose history and native saves; rendering remains pure and independent of seek order. Older controllers infer an initial reference from their own limb geometry. Returning to the baseline pose reuses its exact reference for no-op history.
- Traversal plans are scoped to the existing geometry build, avoiding stale global caches for mutable rig definitions. Initial forward evaluation is linear in figure size; each controller then updates its affected chain/subtree. Nested disjoint chains are solved in ancestor order. Frames without IK retain their original evaluator path.
- `src/ik-joined.mjs` compiles only affected connected IK components into temporary skeletons, aliases joined origins to their parent vertices, and scatters solved angles/lengths back to the original figures. Native topology, figure identities, draw order and assets remain separate. Joins retain stable figure UID and handle identities. Undo and topology snapshots include the affected connected component.
- The editor materializes displayed angles only for FK pose edits that require them. Gestures use the existing object snapshots, cancellation and one-step undo. Root drags with pins use live scoped geometry updates; ordinary rigs retain the existing GPU translation preview. Unchanged objects retain their geometry/resources.
- Authored joined-child snapshots include a changed parent orientation reference even if the child's world angle stays constant. Recomposition after style edits, undo or reload therefore reconstructs the same local articulation as the live preview.
- `src/ik-topology.mjs` repairs controller IDs, chain lengths and outgoing children within existing rig-edit history. Splitting a chain preserves its base; deleted nodes lose their controllers. Copy/paste, duplication and imported figure placement offset copied targets with the copied figure.

## Persistence and boundaries

STYK/STKZ preserve controller metadata and rest lengths. Pivot PIV cannot store these constraints, so its existing export materializer bakes constrained output ticks into ordinary angles/lengths and removes IK metadata. The editable source is preserved. STK is a Pivot figure-definition format and does not carry IK controllers; use STKZ for editable IK figures.

Chains cross native figure joins and stop at the connected assembly's root. Joined roots and outgoing attachments behave like ordinary vertices and branches. Multiple IK limbs may share an origin, but may not share bones; conflicting setup is rejected across joins as well as within a figure. Movieclip internals remain a separate sampled hierarchy. This version does not add joint limits, weighted constraints, pole-target objects, or a general rigging graph. STYK projects retain complete joined assemblies; the existing STKZ export still extracts an individual selected figure.

## Verification

- `node --test tests/ik.test.mjs`: solver edge cases, circular and folded Both trajectories, subpixel extension jitter, longer-chain continuity, deterministic seeks, dual pins, orientation, unpinning, FK edits, interpolation and Pivot baking, authored channels, no-op/cancel/undo, native figure placement, rig edits, Simple drafts, and joined roots.
- `node --test tests/ik-joined.test.mjs`: equivalence with single-figure rigs, constant target-space angles and polygon vertex distances during repeated drags, complete planted feet through root and ancestor rotation, cross-join chains, stretch, unpinning, foot articulation/bend edits, copy remapping, shared-chain rejection, topology undo and persistence.
- `node --test tests/ik-evaluation.test.mjs`: appearance-only solution reuse, exact pose-dependency invalidation, document isolation and deterministic seeks. The joined suite also checks thickness/color/opacity edits with pins enabled and disabled, both with and without property channels, through rebuilds, undo/redo and reload.
- `node tests/ik.browser.mjs`: actual inspector controls and pointer gestures, live dual-foot root dragging, rotation, pin toggling, recovering an unreachable target, and real worker/backend STYK/STKZ/PIV export/reopen. Screenshot and report: `artifacts/ik/`.
- `node scripts/benchmark-ik.mjs`: warmed CPU solver and scoped root-drag evaluation in a 1,000-figure scene, plus verification that unrelated geometry is retained. This excludes GPU completion and display latency.

The browser CLI named by the verification skill was unavailable, so verification uses the repository's installed Playwright/Chrome harness. The npm shim on this machine is broken; equivalent Node script entry points were run directly.

The separate older `tests/rig.browser.mjs` smoke stops at its assertion that pressing R enters Rig. The current app assigns R to temporary Handle Edit (also documented in README). Its later rig gesture/export checks therefore did not run; the IK browser suite does not rely on that shortcut.
