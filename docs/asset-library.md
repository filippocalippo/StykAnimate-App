# Asset library

The Library panel (`src/user-library.mjs`, `src/styles/features/library.css`) has two sources, switched at its top: **My library**, the desktop library of saved assets and folders, and **Community library**, what people share on stykanimate.com (below). Under the switch sit Search, a **Show** kind filter (All, Figures, Movieclips) and the library's **⋯** menu (New folder, Add selection, Refresh, Show in folder, Preview background, Rig examples). The row below names where you are: the folder path with the item count and **New folder** in My library, the website in Community library. The cards form one listbox with a single tab stop; the foot is pinned under them: the status line, then **Add selection** (the website link in Community library). This implements experience.md §5.5 with the website's community library as the second source; the spec's *This project* and *Examples* live in the Add menu and the ⋯ menu's Rig examples.

Select one or more figures, or a movieclip, and choose **Add selection** in the Library's foot or **Add to library** in the Properties footer. The same command is in the canvas context menu and Selection actions. Assets are saved in the folder currently open in My library.

- Drag a figure, set, or movieclip from Library onto the canvas to insert it at the pointer. Double-click or Enter places it at the scene center. Undo removes the insertion in one step. Folders stay in the library.
- Drag assets or folders onto a folder card or a part of the folder path to move them, with a highlighted destination and a move label. Escape cancels a drag; holding near the list edge scrolls it. A folder cannot be moved into itself or its descendants.
- Every card action is in its **⋯** menu, which shows on hover, focus and the selected card (always under touch), and in its right-click menu: Insert or Open, Rename, Move to…, Show in folder and Move to Recycle Bin. Right-click empty library space for the library's own actions. Arrow keys move across a row or to the nearest card above or below; Enter opens or inserts, F2 renames inline, Delete opens the removal dialog, and Shift+F10 opens the menu. Renaming preserves the native extension.
- Thumbnails automatically choose a light, neutral, or dark checkerboard from visible artwork colors so white and dark assets remain readable in either app theme. **Preview background** in the ⋯ menu also offers Light and Dark overrides. These backgrounds do not alter artwork or saved transparent PNGs.
- Hover over a movieclip to play its actual editable animation, including nested clips and native timing, in a looping thumbnail. The preview uses a stable fit of sampled motion, a progress line, and a single contrast background sampled across the clip. Leaving, scrolling, changing panels, dragging, or losing app focus stops the preview. Posters and hover previews are drawn by the app's renderer where it can (one preview worker, kept between hovers and released after five idle minutes); otherwise a disposable worker draws them and is released when the preview stops. Hover rendering is capped at 24 FPS while preserving the clip's playback duration.
- Figure sets preserve their relative positions, pose, internal attachments, and draw order. A selected child without its parent is saved detached at its displayed position. Movieclips retain their nested editable animation and start playing at the insertion frame.

The desktop library is in the OS Documents folder at `StykAnimate/library`, including redirected Documents/OneDrive folders. The Windows setup creates that folder for the current user; first launch also creates it for portable installs and other users. Updates and uninstall retain the user's library.

Single figures and sets use native, compressed `.stkz` files; movieclips use `.stykmov`. Each file has a transparent 320 × 320 PNG sidecar (`name.stkz.png`) and small optional metadata (`name.stkz.json`). Rename and Move carry the sidecars along. Files copied into the library without previews have their previews generated when visible. Refresh, switching to Library, or returning focus to the app detects external changes. Copy the sidecars too to avoid regenerating previews.

Version 0.4.0 extends `.stkz` to contain a set of figures in one pose. Earlier app versions can still open single-figure files but do not support sets.

Preview rendering and native export run in workers. Hover playback decodes the native file in its own worker with one frame in flight and no retained rendered-frame sequence. Native transfers use acknowledged 256 KiB chunks and commit complete files exclusively without overwriting another asset. Colliding names gain a numeric suffix. Library IPC accepts only paths inside the library, rejects links and traversal, and never accepts renderer-selected absolute filesystem paths.

Verification: `npm run test:library`, `node --test tests/library-preview.test.mjs`, `node tests/library-panel.browser.mjs` (with `npm run serve`), `node tests/user-library-ux.desktop.mjs`, `node scripts/smoke-public-library.mjs` (a stand-in for the website's API, so it needs no network; it inserts and saves a figure and a movieclip and restarts the app to check the download count), `node scripts/smoke-library-drag.mjs`, `npm run test:library:desktop`, and `node scripts/smoke-library.mjs --packaged`. `STYK_LIBRARY_DIR` and `STYK_USER_DATA_DIR` isolate automated test storage. `STYK_PACKAGED_EXECUTABLE` selects a versioned release for packaged tests.


## Community library

The website's community library (`/library/`) is a service of stykanimate.com: people upload figures, movieclips and full projects, every upload is reviewed, and approved items are published. The app only reads it. Full projects stay on the website; the panel lists the figures and movieclips it can insert.

- Choose **Community library** in the panel. Assets are grouped by the website's categories (Characters, Effects, Moves, Props, Backgrounds, Animations, Other); Search covers name, category, author, tags and description, and Show filters by kind. Double-click, Enter or a drag to the canvas inserts an asset exactly like a saved one, in one undo step. Its ⋯ menu adds **Save to My library** (into the folder open in My library; the website's WebP poster is converted to the PNG preview the library keeps) and **View on stykanimate.com** (the asset's page, `/library/?item=<id>`).
- `desktop/public-library.cjs` owns every request in the main process. It asks `/api/v1/content` which index is current and where the public files live, then reads the immutable `index/<version>.json`, from the file host the site names when that is stykanimate.com or a subdomain of it, and otherwise through `/api/v1/library/index/<version>`. An unchanged version costs one small request and the catalogue is rechecked at most every ten minutes. Items are validated strictly: ten-character ids, a figure or movieclip, object keys under `i/<id>/`, a size within the kind's limit and a SHA-256.
- Responses are size-bounded (content 256 KiB, index 4 MiB, poster 512 KiB, file 8 MiB for figures and 12 MiB for movieclips) and redirects are refused, except the download redirect below. A poster must really be WebP, PNG or JPEG, and a file reaches the renderer or the library only after its size and SHA-256 match the index. Posters (16 MiB) and files (32 MiB) are cached in memory only.
- The first download of an asset goes through `GET /api/v1/library/get/<id>?k=<key>`, the route the website's own download button uses. It counts the download and redirects to the public file, and the redirect may only lead to stykanimate.com or a subdomain. The asset's id is then kept in `community-downloads.json` in the user data folder (public ids only, at most 5,000, the oldest dropped first), and every later download of it, in this session or another, reads the public file directly. So one person adds one download per asset, however often it is inserted, dragged in or saved, and browsing counts none. A download that failed before the site answered is not remembered and counts on its next try. Downloaded files are verified and kept in memory per asset, so an insert after a save does not fetch again. Only ids and file keys already published in the index are sent; nothing about the user or their projects is.
- The website's **Open in StykAnimate** is `stykanimate://library/<id>`. The main process accepts only ids shaped like the website's, keeps the link until the workspace takes it (so a link that starts the app is not lost), and the Library opens on Community library with the asset selected and focused. The link never writes files or edits the scene by itself.
- Without a connection the Community library says so with **Try again**; an already shown catalogue stays usable. The browser build reads the same library through its own origin (`web/worker.js`) with the same rules (`src/community-library.mjs`), and keeps My library in the browser's storage (`src/web-library.mjs`); see [Web build](WEB.md).
- `STYK_PUBLIC_LIBRARY_URL` points the app at a loopback server for tests; any other address is refused.
- The service's side of this contract is in the website repository (`worker/library.js` and `src/js/library-contract.js`); its `scripts/check-library-compat.mjs` runs this client against the real Worker.
