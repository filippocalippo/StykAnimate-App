# Simple timeline working frames

Simple mode keeps a stored keyframe and a working pose separate. An imported Pivot animation opens at its last stored key with an Add working copy. A selected stored frame opens in Update mode. Edits create a lazy checkpoint of the touched figures and frame fields; the implementation does not clone the animation to start a gesture.

Add stores the working copy as a new final key and preserves the previous stored pose. Update commits the selected key and returns an Add copy of the last stored frame, including when the updated key was in the middle. Selecting another Update key commits the previous key. Reclicking an edited key shows Keep changes / Discard; Discard supports Undo. Structural filmstrip operations also resolve an unadded working copy before acting. These behaviors are verified against the native routes documented in `artifacts/native-static/save-add-draft.md` and `artifacts/native-static/update-frame-return.md`.

Playback, Simple thumbnails, inbetween previews, frame Copy, and Pivot export read the stored frame representation. The editing canvas displays the working pose. Stop returns to that pose and selection. Native Pivot Save excludes an unadded Add copy; accordingly, PIV export restores its stored baseline and never appends implicitly. STYK Save and recovery preserve both poses plus working-mode metadata, so restarting does not lose unadded work. Explicitly switching to Advanced materializes a distinct dirty Add pose as a new key to retain both poses under direct editing.

Shared rig changes transform both the stored checkpoint and visible working pose. They do not append an Add frame. Topology Undo/Redo restores the journal along with the rig, including Undo after Update cleared the journal. Its supplemental history reuses immutable affected-object command snapshots and recovers untouched poses at replay instead of cloning another complete frame. Frame-local edits remain discardable while shared definition and project changes retain their wider lifetime.

Context Paste Insert and single-frame Delete preserve the Add working pose while editing stored keys. Toolbar Paste-to-end returns an Add copy of the last pasted key; Delete-selected returns the last survivor. Each stored-frame command includes its working-copy transition in one Undo command. The static distinctions and native camera, Flip and Color range gates are documented in `artifacts/native-static/add-draft-structural-range.md`. Add-mode appearance and transform changes affect the working copy even when stored frames are selected.

The persisted extension is `_styk.simpleFrameDraft = {version: 1, mode, index, frameId, baseline?, empty?}`. A baseline must have the same frame identity and pass normal scene validation. `empty: true` retains one internal editable placeholder while reporting zero stored keys and zero playback ticks. First Add promotes that placeholder, Undo returns to zero, and deleting all keys retains the current working pose. STYK retains the placeholder; native Pivot export contains zero stored frames. `Editor.frameDraft` reports mode/index/dirty/empty/storedCount, and `frameDraftRevision` invalidates worker snapshots when a metadata-only transition changes the stored representation without changing the document edit revision.

Verification is in `tests/editor-frame-draft.test.mjs`, `tests/pivot-frame-draft.test.mjs`, `tests/pivot-empty-export.test.mjs`, `tests/stored-frame-playback.test.mjs`, and `scripts/smoke-simple-native.mjs`. The source Electron smoke writes `artifacts/simple-native-smoke.json` (11 checks including actual stored-thumbnail pixels, playback, held-gesture Save and Recent Files restart). `scripts/smoke-simple-boundaries.mjs` adds six passing actual desktop checks in `artifacts/simple-boundaries-smoke.json`: zero-key New/Add/Undo/Delete-all, native STYK/PIV save and reopen, context paste/delete history, working-only range edits, and stored playback/export duration. Existing installers predate this source slice until the next release build.

Remaining scope: unsupported direct programmatic multi-frame commands reject an unresolved dirty Add copy before mutation; native context operations use the stored-frame transaction, and other filmstrip actions present the discard decision first. Authored Add copies retain the current direct-channel behavior and need further exact native evaluation where channels overlap the last frame. The application warns on any pending edit, while native Pivot's unstored-frame warning uses an edit-counter threshold of three.
