# Adaptive preview memory

The interface's own painters, thumbnails and library previews use disposable image copies. The document's image URLs, encoded bytes, dimensions and anchor coordinates are unchanged. Preview bitmaps expose their original `naturalWidth`/`naturalHeight`; their actual `width`/`height` describe allocated pixels. The scene canvas does not use them: the engine decodes its pictures on its own workers and uploads them to its atlas ([Engine: rendering](engine/rendering.md#in-the-app)).

`ImageResources` (`src/image-resources.mjs`) enables this with `preview: true`. It inspects PNG dimensions before decoding, estimates the needed pixels from the figure's scale and view resolution, deduplicates URLs, distributes its decoded-image allowance across the current draw, and discards obsolete variants before replacing them. When the caller supplies the visible document rect or a document→output plan (export), each image decodes only the source crop its draw can sample — `srcX/srcY/srcW/srcH` in source pixels — at the needed sampling density. A retained variant serves later draws while it still covers the needed region, and replacements decode the union of old and new coverage while it stays inside the allowance, so pans and zoom-direction changes do not re-decode multi-megabyte sources. The editor's image owner (`src/preview-images.mjs`) uses a serial worker with a coalesced latest request. Zoom can request more detail; stale work cannot overwrite a replacement document. Empty vector-only scenes need no image worker.

For ordinary non-interlaced PNGs, `preview-image.mjs` streams decompression through two scanline buffers and samples into the bounded preview. It supports PNG filters, packed grayscale/palette samples, RGB/RGBA, 16-bit samples and transparency. Embedded colour profiles and interlacing use the browser decoder to preserve their interpretation. Other formats also use the browser decoder. Browser resizing does **not** guarantee bounded transient decoder memory for those fallback cases.

Embedded base64 images use the runtime's native byte decoder when available, avoiding an intermediate binary string and a JavaScript loop over every byte. Older runtimes keep the established fallback. Encoded bytes and MIME types remain identical.

Raster export explicitly uses `preview: false`, but its tile plan still bounds each decode to the source region the output samples: an asset placed mostly off-canvas decodes only its visible crop instead of the full source, so oversized embedded bitmaps no longer exhaust the asset allowance merely by existing. Coverage grows across tiles and frames within the allowance, so moving cameras decode shared regions once. SVG and the existing “No smoothing” path still decode original assets at full resolution. Individual source decodes, the final output canvas and those existing export paths still have browser/format limits; this change does not promise arbitrary-size exports within a fixed amount of RAM.

Animation settings offer fixed Normal (100%, the default), Medium (75%), Low (50%) and Draft (25%) playback quality, plus opt-in Automatic. These preferences affect playback backing density and antialiasing only; editing returns to full density on pause and export never reads the setting. Saved values are normalized, and changing a preference during playback uses the existing atomic resize/repaint transaction without adding a preparation phase. Draft is an explicit choice; Automatic stops at 50%. In Automatic, a frame-rate governor complements the memory-pressure path during playback: a sustained presentation deficit lowers the viewport backing resolution (100% → 75% → 50%) and the WebGPU multisample level (4 → 1 → 1), while six seconds at 98% of the target presentation rate restores each level and pausing resets to full quality. The overlay keeps native density. The same badge reports governor reductions.

`previewMemoryPlan()` centralizes hardware-based retention allocations. Decoded images, raster originals, thumbnails and the library have separate allocations within that policy. Software filter surfaces and immutable background edge rasters have explicit editor and per-worker allocations, included in aggregate reservations. Existing shared artwork and measured prefetch eviction remain active. This is a policy for retained caches, **not** a hard cap on total process memory: the document, temporary transition copies, browser decoding internals, graphics-driver allocations, and export output surfaces also consume memory. Required live resources can temporarily exceed retention targets during atomic scene transitions.

- `node --test tests/preview-image.test.mjs tests/preview-images.test.mjs tests/preview-quality.test.mjs`: preview image decoding, the preview image owner and the quality levels.
