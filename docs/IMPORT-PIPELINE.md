# Native Pivot import pipeline

The desktop application uses the existing authoritative Pivot decoder and preserves its editable report schema. Native v5 imports avoid constructing and serializing a second complete pose inventory in Python: the backend validates the frame table, transfers its original bytes, and the browser builds the editable JavaScript objects once. Legacy PIV, STK and project JSON retain the established decoder and acknowledged JSON transport.

The internal `application/vnd.stykanimate.piv-frames-v1` response contains `STYKPIV1`, a little-endian JSON-header length, the decoded definition/media/header document with an empty `keyframes` array, and the exact validated native frame table. `nativeFrames` records the original byte offset and payload extent. This is an HTTP transfer format, not a replacement for `.piv` or `.styk` files.

`backend/fast_decode.py` validates native frames without allocating pose dictionaries. The optional C++17 scanner in `native/piv-frame-scan.cpp` performs bounds, numeric, topology, reference, order and continuity checks through a fixed C ABI. Its inputs and duration output belong to Python; no native object pointer crosses the boundary. Python remains the fallback when a compatible binary is absent. `/api/health` reports `nativeFrameScanner` and the loaded accelerator's ABI and SHA-256. Windows x64 is executed and tested; other desktop targets require their own scanner build and runtime verification.

The import worker parses the compact JSON header, sends it in acknowledged batches of at most 1 MiB, and transfers the native frame buffer without copying. `src/import-wire.mjs` materializes native fields and ordinary editable arrays in cooperative tasks with a 3 ms scheduling target. Long pose arrays also yield internally. It publishes `keyframes` only after the complete table succeeds. Cancellation, disposal, malformed input and superseded requests cannot publish a partial scene.

Wire/source limits and an estimated 2560 MiB (2.5 GiB) pose-inventory budget are separate checks. The latter accounts for frames, object records, pose scalars and joins before the corresponding allocations; it is an admission estimate rather than a measurement of JavaScript heap usage. The C++, Python and JavaScript paths enforce the same estimate. Scheduler delays, garbage collection and individual native operations can exceed the target task duration.

The source cache retains the original compressed file and compact transfer representation. A caller requesting canonical JSON or native export obtains that representation lazily under the decode lock, which prevents concurrent full Python scene inventories. Original-byte export remains exact when the decoded scene is unchanged. `editor.loadAsync` then performs the editor's semantic validation and index preparation independently before one atomic document publication; see [EDITOR-IMPORT.md](EDITOR-IMPORT.md).

Correctness evidence includes every field and JSON property order in all 23 original native-v5 corpus reports, all 1,479 frames and 208,373 objects in the user's 17.18 MB Akane file, malformed/truncated/cancelled transfers, zero stored frames, lazy-cache concurrency, and exact unchanged native exports. Relevant tests are `tests/import-wire.test.mjs`, `tests/import-wire-review.test.mjs`, `tests/import-wire-akane.mjs`, `backend/test_import_wire_review.py`, and `backend/test_fast_decode.py`. Native/Python differential tests include deterministic byte mutations, truncated inputs, signed UIDs, long join chains and explicit accelerator fallback.

The source-stable one-process diagnostic in `artifacts/matched-app-interaction-cpp-async-clean-v1/report.json` measured cold import to first GPU completion callback at 2016.8 ms and warm import at 1699.1 ms on the tested Windows machine. A later readiness audit found that this first submission preceded the background texture: these values describe an incomplete first submission, not a complete visible imported scene. It opened the last stored key directly and passed both sets of 23 subsequent pose/pixel checks. The initial viewport was vertically offset by 13 pixels from the native benchmark, while the later pose trials used the exact matched transform. Remaining first-render tasks lasted 67/52 ms. These diagnostic results must not be compared directly with native Pivot's different Present-return endpoint or used as complete-scene import latency.

Initial scene preparation now runs before the editor publishes the new document. The model's `prepareScene` hook builds exact initial-frame geometry cooperatively, decodes the background and images used by that frame into a private cache, and prepares GPU buffers and textures without changing the live canvas. The previous document remains usable until preparation succeeds. The document listener then adopts the exact geometry, images, fitted view and GPU resources together. The first normal render uses those retained resources; it does not rebuild the scene or display a frame with missing media. Aborted, superseded or failed preparation releases only the incoming resources. See [renderer.md](renderer.md) for ownership and scheduling limits.

`tests/renderer-initial-scene.browser.mjs` exercises the actual app with a native final stored frame containing an image background, foreground sprite, translucent figure and nonidentity saved camera. All nine checks pass: the first render has complete media, neutral editing coordinates, zero primitive uploads or compilation, and pixels identical to independent fresh rendering and the former upload method. A failed subsequent image decode preserves the prior report, GPU buffers and exact canvas. This small fixture establishes behavior, not large-scene timing; screenshots and machine-readable evidence are in `artifacts/renderer-initial-scene/`.

The subsequent source-stable actual Electron Akane diagnostic measured 2224.2 ms cold and 1640.9 ms warm from file change to the first complete-scene GPU callback. Both first submissions already had decoded media and the required texture-backed background. Initial rendering took 0.6/0.5 ms of CPU wall time with no primitive uploads; scene staging uploaded 1,746,816 bytes in three calls. There were no import main-thread long tasks of 50 ms or more. Retained batch pixels matched the old 615-upload path exactly, and both sets of 23 pointer mutations matched the independent renderer and all 15,697 native pose nodes within 0.000031 world units. This is one diagnostic pair on one Windows machine, with a correctness upload comparison before the gestures. It is not the final three-process timing run, a physical input/display measurement, or a direct speedup comparison with native Present return. Full phase timings, stable runtime hashes, screenshots and qualifications are in `artifacts/matched-app-interaction-atomic-diagnostic-v1/SUMMARY.md` and `report.json`.
