# Frame clipboard

Frame copy/cut/paste now survives document replacement and desktop restart. This follows Pivot's separate application clipboard, including append and insert, as described in the [native frame controls](https://pivotanimator.net/help5-2/animation_frame_controls.htm).

`Editor.copyFrames(indices)` captures selected rows in chronological order. It stores only the figures and backgrounds those frames reference, including embedded image data, font outlines, joins, camera, paint order, hidden exposures and source layer properties. Authored source rows capture their composed pose at the row start. Clipboard snapshots do not share mutable figure or pose objects with the source project, and contain neither the complete original PIV source nor unused library assets.

`pasteFrames(index)`, `appendClipboardFrames()` and `insertClipboardFrames(index)` merge identical definitions/backgrounds and allocate unused destination identities. Cross-document UIDs stay consistent throughout one pasted sequence; same-document UIDs retain figure continuity. Every pasted keyframe receives a fresh frame identity. Foreign file offsets are removed from copied assets. Legacy keyed sprites use their rendered transparent image, legacy COLORREF values become modern opaque overrides, and legacy repeated holds become identical endpoint keys so modern interpolation does not introduce motion.

A paste is one undo operation, including imported assets and layer metadata. Media strings stay out of synchronous history JSON serialization and their retained size is counted directly. Failed preflight validation publishes no assets, source frames, history or identity counters.

## Authored destinations

Insertion shifts existing authored keys by the inserted exposure, retaining their IDs and editable channel structure. Per-layer, Scene and Camera pose keys expose the inserted frames and resume the original animation afterward. Scalar `passthrough` intervals return control to those poses during insertion; this preserves blended backgrounds and prevents absolute camera or figure channels from masking a copied pose. The previous scene, nullable color state and not-yet-started channels resume afterward.

Only interpolation runs affected by insertion receive exact integer-tick pose samples. Connected automatic-easing runs are preserved together because inserting a key changes Hermite tangent context. Unaffected native frames and channel keys remain in place. Planning is bounded to 10,000 local samples, 250,000 preserved object poses and 3,000,000 pose values; exceeding a budget rejects atomically. The synchronous model API remains for small direct callers. UI operations now run this planner in a dedicated terminable worker; completed reports are validated and staged cooperatively before one atomic publication.

## Desktop persistence

`installNativeFrameClipboard(editor, desktop)` subscribes to copy events and writes a self-contained `.styk` clipboard through the document export worker and bounded 256 KiB native chunks. The fixed destination is `userData/frame-clipboard.styk`; the renderer cannot choose its path. A completed file is replaced atomically. `ready` restores asynchronously, `flush()` waits for pending persistence, and a newer copy wins over startup restoration or an older pending save. The native bridge exposes `beginClipboardWrite` and `beginClipboardRead`, reusing token-bound chunk operations.

Browser-only sessions retain the clipboard across documents for the lifetime of the page. Desktop persistence is independent of changing loopback ports and the OS clipboard.

## Background planning contract

The app installs one `ClipboardWorkerClient` on the editor and routes both timelines through `runClipboardOperation(kind, execute)`. `copyFramesAsync`, `cutFramesAsync` and `pasteFramesAsync` accept an abort signal and progress callback. The root wrapper serializes user requests, supplies an active Cancel control after 150 ms, and aborts queued or active work when the document is replaced. An immediate Paste awaits the newest pending Copy. A failed or cancelled copy does not overwrite the prior clipboard or abort its pending native persistence.

Each operation owns a terminable worker. Main-thread snapshots and result validation yield between bounded pieces; authored interpolation and legacy conversion execute in the worker. Native Copy projects only selected stored frames and referenced definitions. The worker owns its received data, so capture and restore avoid redundant frame clones. The synchronous editor methods remain available for small direct callers and correctness comparison.

Native Paste sends destination timing/key identities and cached UID/capacity metadata without sending unchanged destination poses or original PIV bytes. For same-version native files, cooperative exact asset preflight retains the first equivalent destination match and sends only matched copied definitions plus all reserved IDs/counts; unrelated destination assets are omitted. Changed definitions and colliding IDs still allocate exactly as in the synchronous planner. Legacy-to-modern sources keep the full asset-table route for worker-side conversion. No persistent fingerprint cache or ID-only equality assumption is used.

The worker returns only inserted frames and asset/layer deltas. Cooperative preparation adopts the exclusively decoded result as immutable history and makes one independent live copy; the public preparation API still defensively copies caller-owned input. A standard sparse command preserves untouched frame identities and reusable Undo/Redo. Authored destinations, Simple journals, held model gestures, legacy upgrades and Cut retain the isolated full-report fallback with private before/after snapshots. History accounts for expanded retained data separately from compressed transfer bytes. The app's normal command boundary first finishes active input capture.

## Legacy destinations

Pasting Pivot 5 content into a Pivot 2, 3 or 4 destination now upgrades that destination as part of the same undo command. The conversion preserves legacy integer-tick holds with identical endpoint keys, converts legacy colors and keyed sprites, retains frame identities used by authored channels and leaves the original PIV bytes available for STYK and exact Undo. The Advanced timeline selects only the newly pasted keys even when conversion expands old holds. Simple working copies, including a document with zero stored frames, remain separate from stored keys.

The backend builds a fresh Pivot 5 scaffold when the document has been upgraded but its retained source is legacy. It validates the original source version and fingerprint rather than trusting metadata. Undo restores the original report, counters and version; Redo restores the complete modern paste. Conversion and paste preflight run in an isolated editor before publication. UI conversion runs in the dedicated worker. Main history stores private before/after report references and prepared indices behind a small command, so publication/Undo/Redo avoid a full-report clone. This full-report route is separate from the ordinary native sparse path.
