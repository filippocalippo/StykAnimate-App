# Native movieclip authored-key capacity

Eight actual editor-built families contain 56 command calls after the owning JavaScript non-progress correction. Maximum, last-safe allocation, one/two collisions, reuse of an existing key at maximum, and maximum/last-safe fractional ticks preserve exact result/error, document, selection, counters, history and events at every step. Input documents serialize and reopen before recording. Ordinary undo/redo and branch replacement follow each insertion attempt.

The valid double collision formerly hung because incrementing an unsafe floating-point counter stopped making progress. `tests/movieclip-key-capacity.test.mjs` proves the original owner times out, then verifies the corrected insertion returns the existing invalid-counter error with saveable document/source table/history/counters/events unchanged. An existing key at the maximum counter still succeeds; last-safe allocation advances to the maximum safe counter. Completed authored draft validation checks the counter header before key ticks, including fractional error priority.

Rust uses the existing native range pose/draft/publication owners. Allocation and completed-counter checks run before source capture, UID hints, selection or publication. Whole-key validation remains strict. No new command/gate/runtime admission or public crate API is introduced. Current local Session/history/publication base remains the explicitly declared count-only recorded-tool harness; canonical prepared worker publication, history-byte settings and full optional selection metadata are separate shared dependencies. No app/GPU/WASM or D7/performance certification is claimed.
